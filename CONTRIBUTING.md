# Как контрибьютить

Репозиторий делит команда: скиллы читают разные агентские системы, поэтому любое изменение
проверяется машинно и попадает в `main` через pull request. Здесь описан процесс; правила
написания самих скиллов — в [`AGENTS.md`](AGENTS.md), требования к frontmatter — в
[спецификации Agent Skills](https://agentskills.io/specification).

## Быстрый цикл

```bash
git clone <repo-url> && cd agent-skills
git checkout -b skill/<кратко-о-чём>       # или fix/<что-чиним>
node scripts/install.mjs --scope project   # разложить скиллы по каталогам агентов
# ... правки в skills/<имя>/ ...
node scripts/validate-skills.mjs           # обязательная проверка
git commit -m "<имя скилла>: что изменилось"
git push -u origin HEAD
```

Дальше — pull request. CI гоняет `validate-skills.mjs` и сухой прогон установщика; мерж после
зелёного CI и одного согласия.

## Что можно присылать

| Тип изменения | Обязательные проверки |
| --- | --- |
| Новый скилл | `validate-skills.mjs`; в описании PR — кто задача-владелец и откуда взята процедура |
| Правка текста/граблей в существующем скилле | `validate-skills.mjs` |
| Правка `templates/builder.py` или `scripts/check_page.py` внутри скилла | плюс прогон: `python3 templates/builder.py --out /tmp/page.json && python3 scripts/check_page.py /tmp/page.json` — обе команды должны завершиться с кодом 0 |
| Правка `scripts/*.mjs` (инфраструктура) | плюс `--dry-run` установщика; в PR — что именно печатает команда |
| Перевод скилла на другой язык | не переводить по частям: либо весь скилл, либо ничего |

Правило одного внимания: **один PR — одна тема.** Новый скилл + правка инфраструктуры в одном
PR рецензируются плохо и откатываются тяжело.

## Требования к PR

1. **Заголовок**: `<имя скилла или область>: что изменилось` — например
   `dashboard-build: добавил чек-лист приёмки макета`.
2. **Описание**: что изменилось, зачем, и что проверено машинно (скопируй вывод команд).
   Если правило родилось из конкретного провала — опиши симптом и вывод, без номеров задач
   и дат.
3. **Один согласующий** (любой участник репозитория) + зелёный CI.
4. Без секретов, токенов, строк подключения и выгрузок боевых данных — ни в тексте скилла,
   ни в примерах, ни в описании PR.
5. Скилл — процедура, а не лог: ни номеров задач, ни дат, ни историй инцидентов.

## Версионирование скиллов

- `version` во frontmatter — semver самого скилла. Патч — правка текста и граблей, минор —
  новый шаг/раздел или новый вспомогательный файл, мажор — смена порядка этапов или формата
  артефактов.
- Меняешь поведение — поднимай версию. Команда обновляется командой
  `hermes skills update` (или переустановкой тем же установщиком), и по версии должно быть
  видно, что именно приехало.
- Пути к файлам внутри скилла менять свободно; **имя каталога и `name:` — публичный
  идентификатор**, он ломает установки у коллег. Переименование — только с явным указанием
  в PR и предупреждением участников.

## Definition of done

- [ ] `node scripts/validate-skills.mjs` — без ошибок;
- [ ] если менялись шаблоны/проверки скилла — прогон сборщика и `check_page.py` с кодом 0;
- [ ] `description` отвечает на вопрос «когда применять», а не «что это»;
- [ ] вспомогательные файлы лежат внутри каталога скилла (`references/`, `templates/`,
      `scripts/`, `assets/`), а не в корне репозитория;
- [ ] нет абсолютных путей чужой машины, секретов и боевых данных;
- [ ] `version` поднят, если менялось поведение;
- [ ] в PR описан способ проверки, которым рецензент может повторить результат.

## Что происходит после мержа

- Скиллы из `main` подхватываются теми, кто подключился через tap: `hermes skills update`
  у каждого — по требованию, не мгновенно.
- Кто ставил через `--mode copy` — переустанавливает: `node scripts/install.mjs --scope user`.
- Кто ставил ссылками (`--mode link`, по умолчанию) — ничего не делает: правка в репозитории
  уже видна всем агентам на машине.

## Если скилл конфликтует с личным

Приоритет каталогов: **проектный → локальный профиль → внешние каталоги**. Одноимённый
проектный скилл перекрывает личный. Если скилл из репозитория ведёт себя как старый —
проверь, не перекрывает ли его копия в личном каталоге (`~/.hermes/skills`, `~/.claude/skills`,
`~/.agents/skills`), и убери лишнюю.
