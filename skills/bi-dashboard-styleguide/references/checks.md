# Правила проверки стиля

Чекер — **независимый** от сборщика: читает только готовый файл страницы и не знает, чем он собран.
Запуск:

```bash
python3 scripts/check_style.py page.json              # отчёт по правилам, код 1 при нарушениях
python3 scripts/check_style.py page.json --json       # тот же отчёт машинно
python3 scripts/check_style.py page.json --scale 12,14,16,20,28
python3 scripts/check_style.py page.json --allow-text "Наши слова"
```

Скрипт печатает по каждому правилу `OK` или `НАРУШЕНО` и в конце итог; код возврата `1`, если
есть нарушения, иначе `0`. Такой чекер ставят в CI и в приёмку — «стиль пройден» перестаёт быть
вопросом вкуса.

## Правила и что каждое читает

| правило | что проверяет |
|---|---|
| кегли видимых надписей из шкалы | кегли заголовков блоков, подписей и чисел осей, легенды, подписей значений, шапки и ячеек таблицы, переменных текстовых виджетов, подписей сегментов круговой, текста фильтров |
| тона по ролям | уровни темы у видимых надписей: значения 1, единица и акцент 2, подписи 3, заголовки 4; уровень 5 — только фон шапки таблицы |
| сетка и линии осей | `showGrid` / `showAxis` во всех осях всех виджетов выключены |
| шрифт темы | ни одного `fontFamilySettings` с `isActive: true` и непустым `fontFamily` |
| нет донорских текстов | поиск по всему файлу стоп-слов проекта («Ось показателей», «Итоги», «Подзаголовок», название шрифта донора и т. п.; список — параметр `--forbidden`) |
| подложка | `backgroundSettings.blur` = 0 у всех |
| рамка и радиус | `borderSettings.isActive` = false у всех; `radius` — одно значение на страницу |
| тени | `shadowSettings.isActive` = false у всех |
| зум и прокрутка | `verticalZoom` / `horizontalZoom` погашены у всех графиков |
| легенда | у односерийного графика легенда выключена (она дублирует заголовок); у круговой — включена |
| бары от нуля | `indicators[].fictionalMinAndMax.min` = 0 у столбцов |
| линии сплошные | `indicators[].settings.elementSettings.parameters.isDotted` = false |
| панель инструментов | `toolboxSettings.isShow` включён только у таблиц |
| метка ИИ | `isAiGenerated` / `showAiGenerated` сняты у всех виджетов |
| отступы кратны базе | все паддинги и `indentation` кратны базе (по умолчанию 4) |
| единообразие | виджеты одного типа совпадают по сигнатуре ключевых настроек — расхождение печатается списком ключей |

## Что чекер не может и что смотреть глазами

1. **Порядок уровней темы** (какой уровень темнее) — в файле только ссылки, порядок знает платформа.
2. **Авторазмеры** платформы: если `fontSize` у подписи не задан, размер выбирает платформа —
   проверить, что он попал в шкалу.
3. **Настройки, которых нет в файле вовсе** (поведение фонов, панель инструментов у типов без
   образца) — платформа может нарисовать иначе, чем в образце.
4. **Визуальные последствия нормализации** — смена радиуса, позиции подписей оси, авто-границ оси
   значений. Их смотрят на странице и записывают решением в гайд.

## Почему чекер отдельный от сборщика

Сборщик проверяет то, что сам проставил, и почти всегда «проходит» — включая случаи, когда
в виджетах осталось донорское наследие: сетка, чужой шрифт, донорские тексты. Независимый скрипт
читает файл целиком и находит расхождения, которых генератор не видит. Расхождение отчётов
сборщика и чекера — сигнал, что проверка сборщика смотрит не на те ключи.
