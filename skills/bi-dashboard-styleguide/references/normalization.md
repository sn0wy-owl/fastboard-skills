# Нормализация настроек визуализации (донорское наследие)

Виджеты почти всегда — клоны **разных** доноров: один пришёл из боевого проекта, другой из старой
страницы, круговая вообще из чужой выгрузки. Вместе с формой приезжают настройки, которых никто
не выбирал: у одного графика активен шрифт донора, у другого включена сетка, у третьего в скрытом
заголовке остался чужой текст. Раскладка при этом выглядит нормально, а панель «Настройки
визуализации» показывает дефолты чужого проекта — именно так это и звучит от заказчика:
«настройки просто в дефолтном состоянии».

Нормализатор — функция, которую проходит **каждый** виджет после клонирования. Правило-ориентир:
**виджеты одного типа совпадают по настройкам** (кроме имени, данных и места).

## Что вычищать

| что | где живёт | как должно быть |
|---|---|---|
| шрифт донора | `*Settings/fontFamilySettings` (`isActive`, `fontFamily`) во всех секциях | шрифт темы: `isActive: false`, `fontFamily: ""` |
| сетка | `axis*Settings.showGrid` | `false` во всех осях всех виджетов |
| линия оси | `axis*Settings.showAxis` | `false` (разделяет тон и подпись, а не линия) |
| имя оси | `axis*Settings.name.text` | пусто (`"Ось показателей"`, «Ось доп. показателей» — донорские) |
| скрытый заголовок | `header.text`, когда `header.isShow: false` | пусто (в панели настроек видно чужой текст) |
| подзаголовок | `header.description.text`, `viewSettings.description.text` (в т.ч. у групп фильтров) | пусто («Подзаголовок» — плейсхолдер донора) |
| заголовки итогов | `headerSettings.customTitle`, `subtotalsSettings.customTitle`, `totalRowSettings.customTitle` | пусто — **три секции**, забывают две |
| подложка | `styleContainerSettings.backgroundSettings.blur` | `0` (у части доноров 10 — «матовое стекло») |
| рамка | `styleContainerSettings.borderSettings` (`isActive`, `width`, `radius`) | `isActive: false`, `width: 0`, радиус один на всю страницу (частая ловушка: `isActive: true` при `width: 0`) |
| тень | `styleContainerSettings.shadowSettings` | выключена; спящие значения привести к одному виду (`blurRadius`, `offsetX`, `offsetY`) |
| подписи осей | `axis*Settings.label.value` / `label.properties.fontSize` | кегль из шкалы (обычно минимальный); у одного донора 8, у другого 12 |
| позиция подписей | `axis*Settings.tickLabel.position` | одно значение (`edge` / `center` вперемешку у разных доноров) |
| границы оси значений | `axisIndicatorSettings.minAndMax` | обнулить/авто: у одного виджета `max: 1`, у другого 500 |
| скрытый зум | `verticalZoom` / `horizontalZoom.settings` | погашен и **один и тот же** блок у всех графиков |
| анимация | `styleSettings.pieAnimationElement` у круговой | выключена — статика честнее для чтения значений |
| «реальная палитра» серий | `colorBySettings.isActive`, `elementColor`, `incisions[].colors` | выключено/пусто: перенос чужой палитры ломает валидацию и цвета уезжают на чужие id |
| отступы донора | паддинги текста 22 px, `indentation` 15 / 10 / 2 | привести к шкале (20 / 16 / 12 / 4) — см. `tokens.md` |

## Порядок внутри сборщика

1. Клон донора → сантайз чужих ссылок (SQL, палитры, чужие id) → привязки и тексты проекта.
2. **Нормализатор** — одним проходом по виджету: шрифты, оси, тексты, контейнер, зум, анимация,
   отступы. Не «правкой по месту» в каждом виджете: иначе следующий донор снова принесёт своё.
3. Самопроверка — отдельным блоком, после сборки.

## Ловушки

- **Порядок вызовов.** Если нормализатор определён ниже вызовов виджета — падение с `NameError`;
  если нормализатор ставит кегль заголовка после того, как сборщик выставил свой — заголовки
  поедут. Нормализатор — последний в конвейере виджета.
- **Не удалять ключи, а менять значения.** Набор ключей клона обязан совпадать с образцом своего
  типа: удалённый ключ меняет отрисовку и ломает сверку с донором. Вычищают **значения**.
- **Спящие настройки тоже видны.** Тени, зум, `subtotalsSettings` выключены, но их значения
  показываются в панели и попадают в диff — приводить к одному виду, а не игнорировать.
- **Изменение радиуса и позиции подписей — видимое.** После нормализации это стоит посмотреть
  глазами и записать решением в гайд (у карточек мог быть радиус 20, у остальных 8).
- **Однотипность проверять машинно.** Сравнивать сигнатуру ключевых настроек внутри группы
  одного типа виджета; расхождение — не «оттенок», а недоделанная нормализация.
