# SVG: получение и применение в Fastboard

## 1. Получить исходник

1. Сначала проверь файлы пользователя и рабочие доноры. Если пользователь уже
   вставил подходящий SVG в FB, используй его как образец конфигурации и стиля.
2. Если доступен браузер, ищи в нём SVG по смыслу объекта: например,
   `roof outline svg`, `radiator outline svg`, `excavator outline svg`.
   SVG Repo и аналогичные каталоги подходят, если доступны пользователю.
   Для набора иконок выбирай единый стиль: контур/заливка, толщина линий,
   пропорции, цвет. Учитывай лицензию и атрибуцию конкретного ресурса.
3. Открой карточку изображения и сам `.svg`, а не только результаты поиска.
   Получи исходный XML через просмотр исходника, загрузку файла или доступный
   браузерный запрос. Для cross-origin fetch возможен CORS: тогда открой прямой
   SVG в отдельной вкладке или используй штатную загрузку. Не обходи ограничения.
4. Убедись, что получен `<svg ...>...</svg>`, а не HTML страницы каталога,
   сообщение об ошибке или растровое превью. Сохрани исходник рядом с артефактами
   проекта; для чужого ресурса зафиксируй URL и условия использования.
5. Если браузера нет, сайт недоступен или исходник получить не удалось,
   запроси у пользователя файл `.svg` либо исходный код SVG. Пример:
   «Не могу открыть каталог изображений. Пришлите SVG-файлы для кровли,
   отопления и окон или их исходный SVG-код; затем вставлю их в Fastboard».
   Не утверждай, что скачал файл, если видел только превью. Не заменяй SVG
   символом, emoji, PNG или самодельной иконкой без согласования.

## 2. Подготовить SVG

- Проверь `xmlns="http://www.w3.org/2000/svg"` и корректный `viewBox`.
  Сохрани пропорции; размеры 800×800 в исходнике не означают размер виджета.
- В `svgContent` передавай XML, начиная с `<svg`, без XML-декларации,
  `DOCTYPE`, обёртки HTML и префикса `data:image/...`.
- Не исполняй содержимое скачанного файла. Проверь и исключи `script`,
  обработчики событий `on*`, `foreignObject`, внешние ссылки/ресурсы,
  если они не нужны для изображения. Если безопасная очистка меняет вид,
  запроси другой исходник, а не выдавай изменённый файл за оригинал.
- Для перекраски проверь и `fill`, и `stroke`: контурная иконка может иметь
  `fill="none"`. Не делай её залитой случайной заменой всех атрибутов.

## 3. Применить в FB через медиа-блок

Проверенный путь: переменная медиа-блока с векторными настройками. Это не
`containerBackgroundImage`, не картинка страницы и не текстовый символ.

1. На целевом стенде выбери рабочий медиа-блок с SVG. Сними его полную
   конфигурацию через UI/API и сохрани резервную копию перед изменениями.
   Если донора нет, создай медиа-блок в UI, добавь переменную и найди её
   векторные/SVG-настройки; названия разделов могут отличаться между версиями.
2. Для независимой иконки клонируй рабочий блок. Назначь новый `id` виджета,
   правильный `pageId`, новый `id` переменной, осмысленное имя и координаты.
   Для правки существующей иконки сохрани её `id` и несвязанные настройки.
3. Оставь переменную с именем `var0`. В её настройках включи векторный режим,
   вставь исходный XML и задай размер SVG. В тексте медиа-блока используй
   `{{var0}}`, включи отображение текста. Сохрани остальные поля рабочего
   донора, включая форматирование и настройки блока переменной.

Минимальный фрагмент настройки (не полный объект виджета):

```json
{
  "dataSettings": {
    "variables": [
      {
        "name": "var0",
        "settings": {
          "vectorSettings": {
            "isVector": true,
            "svgSize": 48,
            "fontColor": null,
            "svgContent": "<svg xmlns=\"http://www.w3.org/2000/svg\" viewBox=\"0 0 48 48\" fill=\"none\" stroke=\"#12233f\" stroke-width=\"2\"><path d=\"M6 24L24 6l18 18M12 20v22h24V20\"/></svg>"
          }
        }
      }
    ]
  },
  "viewSettings": {
    "text": {
      "text": "{{var0}}",
      "isShow": true
    }
  }
}
```

4. Начни с `svgSize=48` в виджете примерно `52×52`; подбери размер по
   фактическому рендеру. Для ряда этапов выдержи одинаковый размер иконок,
   отступ от названия и вертикальное выравнивание внутри строки.
5. Убери дублирование: отключи прежний `containerBackgroundImage`, если
   он был попыткой вставить эту же иконку. Не затирай нужный фон карточки.
   Не удаляй графики, KPI, переменные данных и события соседних виджетов.
6. Сохрани через UI либо API целевого стенда. При API используй актуальный
   полный массив виджетов, прочитай `last-settings-timestamp` перед записью,
   проверь, что после чтения не появились конкурирующие правки. При добавлении
   виджетов добавь их ID в слои страницы; существующие слои не переставляй
   без необходимости. Форматы запросов: [api-roundtrip.md](api-roundtrip.md).
7. Сохрани тот же способ вставки в сборщике, если он используется: следующая
   пересборка не должна вернуть пустую фоновую картинку вместо SVG-переменной.

## 4. Приёмка в браузере

1. Перечитай сохранённый объект: `isVector=true`, непустой `svgContent`,
   имя переменной и шаблон совпадают, ID и слои корректны.
2. Открой целевую страницу, выведи вкладку на передний план. Дождись нужных
   виджетов, а не только шапки приложения; после обновления рендер бывает
   постепенным. Сделай снимок и действительно просмотри его.
3. Проверь, что каждая иконка видна, не обрезана, не растянута, соответствует
   этапу, не дублируется старым изображением и не перекрывает название.
   Проверь, что рабочие графики и KPI сохранились.
4. Ответ API `200` и наличие SVG в JSON не равны визуальной приёмке. Если
   браузер недоступен или рендер не завершился, так и сообщи; не пиши
   «проверено в браузере», когда проверил только конфигурацию.

## Примеры решений

- «Добавь значки рядом со всеми этапами, кровлю я уже сделал»:
  прочитай рабочую переменную кровли, получи остальные исходники через браузер,
  клонируй способ `vectorSettings` и проверь весь ряд на снимке.
- «Нужны SVG, но браузер не подключён»:
  запроси файлы/исходники у пользователя. После получения настрой медиа-блоки;
  при отсутствии браузера отдели проверку JSON от неподтверждённого рендера.
