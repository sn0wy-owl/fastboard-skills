# FastBoard — база знаний (из курса Stepik 246949, пройден 2026-07-15)

Целевой инстанс: URL стенда пользователя (не хардкодить demo/stage).
Официальная документация: https://help.fastboard.online/
FastBoard — продукт ООО «ВИН СОЛЮШЕНС».

## Архитектура платформы
Три рабочие области:
1. **Менеджер проектов** — потоки (папки проектов) и проекты. Новые проекты создаются ТОЛЬКО в личном потоке «Черновики». Публикация = ПКМ → «Переместить» в общий поток.
2. **Конструктор дашбордов** — холст; панель виджетов слева, настройки справа, навигация по страницам сверху.
3. **Диспетчер данных** — подключения (коннекторы), скрипт загрузки, модель данных.
Плюс **Панель администратора** (только роль Администратор): Пользователи, Группы, Активные директории, Подключения, Задания, Лицензии, Потоки, Настройки (версии проектов, шрифты).

## Роли (по возрастанию прав)
Зритель → Аналитик (конструктор, свои потоки, но не источники) → Разработчик (+ диспетчер данных, все коннекторы, RLS) → Администратор (всё + лицензии). Лицензии двух типов: «Аналитик» (зритель+аналитик), «Разработчик» (разработчик+админ).

## Безопасность доступа
- SLS (Stream Level Security) — доступ к потокам.
- PLS (Page Level Security) — доступ к страницам проекта.
- RLS (Row Level Security) — фильтрация строк, настраивается в модели данных через переменные (например регион ↔ менеджер). Тестируется режимом предпросмотра.

## Данные
Источники: файлы (XLSX/XLS, CSV, TXT, JSON, XML, авто), СУБД (ClickHouse, PostgreSQL(+GreenPlum), MSSQL, MySQL, Oracle, Hive), REST-API.
REST-API коннектор создаётся через Swagger: `<backend>/docs/swagger`, метод «Создание источника данных»: {name, driver: "rest-api", credentials: {url, method, format, auth/limit/offset/timeout}}. JSON разворачивается в плоскую таблицу c именами parent_child (Valute_AUD_Value).
Внутренняя БД проекта — ClickHouse (SQL-диалект ClickHouse!).
**Скрипт загрузки** — секции DEL (DROP/ALTER), CREATE, READ (+ OPTIMIZE ... DEDUPLICATE), режимы DROP (пересоздание) и ALTER (инкремент). Русские названия транслитерируются автоматически.
**Модель данных** — связывание таблиц (LEFT/INNER JOIN) по ключам, одна основная таблица (иконка), метрика «плотность ключей» (100% = полное соответствие). ОБЯЗАТЕЛЬНО сохранять модель после правок. Несколько независимых моделей в одном проекте допустимы.
**Обновление по расписанию** — CRON-задания (ежечасно/ежедневно/еженедельно), мониторинг во вкладке «Задания» админки.

## SQL в виджетах (ClickHouse)
Пользователь пишет только семантику: выражения разрезов/показателей, WHERE, GROUP BY, HAVING, ORDER BY. SELECT/FROM/базовая группировка по разрезам генерируются автоматически.
- Порядок: WHERE → GROUP BY → HAVING → ORDER BY.
- sumIf(value, cond) — условные суммы (доля возвратов и т.п.).
- Форматированная дата = строка → для правильной сортировки добавить GROUP BY date и ORDER BY date (или позиционные ORDER BY 1).
- При DrillDown в запрос попадает только текущий разрез → в сортировках использовать позиционные аргументы.
- «Показатель на дату» рядом с показателями за период: паттерн arraySum(arrayMap((p_period,...,p_value), lambda, if(p_period=MAX(period),p_value,0), groupArray(...)...)).
- Сравнение с прошлым периодом: календарь со смещениями (offset '0', '-1M', ...), join по date_id (toYYYYMMDD(date), UInt32); все меры пишутся как sumIf(x, offset='0'); осторожно — календарь множит строки по числу смещений.
- В медиаблоке (KPI) под капотом LIMIT 1 → «значение на последнюю дату» = GROUP BY date ORDER BY date DESC.

## Визуализация
Виджеты: линейные/столбчатые (в т.ч. нормированные, накопленные, комбо), круговые, тепловые карты, таблицы (плоские/сводные), спарклайны, медиаблоки (текст+графика+переменные {{var0}}, слайд-шоу, SVG-иконки по ссылке — Icons8), фильтры (календарь, кнопки, списки), триггеры.
Настройки виджета: вкладки Данные / Вид / События. Стратегия цвета: глобальная по разрезам ИЛИ по показателям (не обе); локальный цвет приоритетнее глобального; чтобы вернуть глобальный — выключить переключатель цвета в настройках показателя, а не просто убрать цвет.
Виртуальные данные: автогенерация демоданных для макетирования с заказчиком до подключения реальных (значения разрезов можно править вручную).
Фильтры: глобальные (на все страницы), исключение виджета из фильтрации — вкладка «События»; фильтрация кликом по точке данных; SQL-трансформация значений фильтра.
События/триггеры: true/false-переменные, управление видимостью виджетов (скрытые виджеты не шлют запросы), всплывающие панели.
Прочее: защита проекта (ПКМ → Защитить), откат версий (история, хранится 100 версий по умолчанию), экспорт графика в Excel через ПКМ, режим просмотра для проверки глазами зрителя, экспорт/импорт страниц между проектами.

## Методология красивого дашборда (мастер-класс курса)
1. Сначала макет на виртуальных данных, согласование с заказчиком, потом данные («чистый» подход).
2. Z-паттерн чтения: верх — заголовок+фильтры; центр — KPI и ключевые диаграммы; низ — детальные таблицы.
3. Акценты: цвет, размер, обводка; светло-серый фон вместо белого; обязательные заголовки у всех виджетов.
4. Палитры — готовить в Figma; иконки — Icons8 по ссылке; вдохновение — Dribbble/Behance; UX-законы — lawsofux.
5. Размер страницы задаётся в правой панели (пример курса: 1360×1260 px).
