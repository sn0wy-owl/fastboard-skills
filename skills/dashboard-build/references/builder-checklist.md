# Сборщик страницы: инварианты и самопроверки

Страница платформы собирается скриптом. Файл страницы руками не правится: каждая правка —
строка в скрипте и повторный прогон. Скелет — `templates/builder.py`, независимый валидатор
готового файла — `scripts/check_page.py`.

## 1. Единая сетка

Две константы — поле доски и зазор между виджетами. Все координаты выводятся из них:
`width = (board_w − 2·pad − (n−1)·gap) / n`. Проверка в конце прогона печатает поля со всех
четырёх сторон и список всех зазоров: у клонов геометрия «гуляет» (карточки 380 с зазором 15
давали правый край 1585 при левом 20, а нижнее поле 24 против 20 сверху).

Отдельно принимается решение, какие ряды намеренно короче общего правого края — это выбор,
а не ошибка; но он должен быть записан, чтобы приёмка его не «исправляла».

## 2. Детерминированные id

- `PAGE_ID` — константа в сборщике.
- id виджетов, разрезов, показателей, переменных, фильтров и групп — `uuid5` от постоянного
  пространства имён и имени объекта: `uuid5(NS, "widget|Выручка по месяцам")`,
  `uuid5(NS, "incision|Выручка по месяцам|Месяц")`. Имя, а не порядок, задаёт id.
- Платформа импортирует по id: новый id страницы → создаётся **новая страница** вместо
  обновления, новый id виджета → дубликат виджета.
- Проверка: два прогона подряд дают одинаковый набор id; пустой ключ имени падает с ошибкой.

## 3. Доноры формата

Виджеты клонируются из боевого экспорта по одному на нужный тип (столбцы+линия, горизонтальные
столбцы, таблица, «прогрессбар» для KPI, текст, круговая). Сборщик печатает имя взятого донора
и состояние его осей: в выгрузках встречаются почти одноимённые виджеты («Линейная диаграмма 1»
и «Линейная диаграмма 1 (8) (2)»), а поиск по подстроке берёт первый.

**Наборы ключей нового виджета должны совпадать с образцом того же типа.** Добавленный «лишний»
ключ ломает соответствие эталону.

## 4. Сантайз чужого

Обнулять, а не переносить: SQL-запросы (в том числе внутри условий окраски), палитры по чужим
id, сортировки по чужому показателю, накопление показателей, ссылки на переменные чужого
проекта, ключи-словари вида `<id страницы>`, алиасы цветовых правил с чужими id.

Финальная проверка — два шага, оба обязательны:

1. собрать множество **своих** id (страница, виджеты, фильтры, разрезы, показатели, переменные)
   и вычистить любую uuid-строку вне этого множества — висячие ссылки ловит валидатор платформы;
2. поиском по файлу убедиться, что не осталось имён чужих таблиц и полей.

Помни: легко вычистить свои id вместе с чужими. Забытая категория даёт пустые id (`pageId: null`,
`variables[].id: null`), и платформа не различает объекты.

## 5. Макет без модели

Если источника ещё нет: привязка к модели пустая, режим макета выставлен, значения разрезов
задаются явно человеческими названиями категорий, диапазоны показателей — по смыслу метрики
(не унаследованные от донора). Запасные значения донора нужно переписать явно: без этого
в макет уезжают «январь…декабрь» чужой страницы.

## 6. Единицы измерения

Один словарь единиц на весь сборщик (`UNITS` + `set_unit`). Единица выставляется каждому
показателю отдельно: в KPI-подписи, в каждом графике и в таблице должна читаться одна и та же.
Донорские диаграммы приходят с чужим суффиксом «%» даже у выручки — проходить по каждому
показателю и выставлять единицу по смыслу метрики.

## 7. Слои отрисовки

Порядок отрисовки строится явно, снизу вверх; в него входят виджеты, фильтры и группы.
Оверлей (спарклайн, шкала) обязан лежать **выше** своего фона, иначе своя же подложка перекроет
текст карточки. Пустой список слоёв — источник перекрытий. Проверка: каждый элемент в списке
ровно один раз, `index(overlay) > index(background)`.

## 8. Обвязка — флагами, а не по одному виджету

Рамки, ползунки приближения, панели инструментов, метка «сделано ИИ» включаются и гасятся
**сразу всем классом виджетов**: после правки одного графика у остальных обвязка остаётся
и разъезжается. Заводить в сборщике флаги (`borderless=True`, `no_zoom=True`, `ai_label=False`)
и применять их ко всем большим диаграммам.

## 9. Самопроверки в конце прогона

Обязательный минимум, с печатью результата:

- поля доски со всех четырёх сторон и все зазоры;
- ни один блок не выходит за доску;
- все id непустые, уникальные, входят в множество своих;
- в файле нет чужих uuid, имён чужих таблиц, чужого SQL;
- все привязки к модели либо заполнены, либо осознанно пусты (режим макета);
- заголовки, подписи, единицы заполнены у каждого виджета;
- метка «сделано ИИ» выставлена по решению брифа, а не унаследована.

## 10. Отчёт о сдаче

Файл + короткий отчёт: что проверено машинно, что смотреть глазами при первом импорте, какие
решения приняты по умолчанию, что осталось незакрытым. Отдельно — список типов виджетов,
подтверждённых только образцом, а не платформой.
