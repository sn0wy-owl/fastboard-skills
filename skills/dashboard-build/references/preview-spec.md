# HTML-предпросмотр и приёмка макета

Предпросмотр — не «красивая картинка», а чертёж: по нему принимается решение о раскладке,
и только после него собирается страница платформы. Сkelet: `templates/dashboard-preview.html`.

## Обязательные свойства

1. **Реальные координаты доски.** Ширина доски задаётся в пикселях (например 1600), все блоки
   расставлены в этих же координатах. Если страница не влезает в экран — масштаб через
   `transform: scale()`, а не пересчёт размеров: цифры в макете должны совпадать с цифрами
   в сборщике.
2. **Видимая сетка.** Поля доски и зазоры между виджетами показаны (или включены флагом):
   заказчик должен видеть, что поля равны со всех четырёх сторон, а не «примерно одинаковые».
3. **Типографика как в платформе.** KPI-карточка: подпись метрики, значение, единица, динамика —
   то же расположение и тот же порядок кеглей, что будут в собранной странице.
4. **Заглушки помечены на странице.** Любое выдуманное число несёт пометку (плашка «макет»,
   серый цвет, сноска), а не только упоминание в ответе агента.
5. **Легенда рядом с макетом.** Таблица: блок → метрика → единица → источник (реальные данные /
   заглушка) → чего ещё нет в макете.
6. **Ничего лишнего.** Макет — чертёж, а не презентация: никаких анимаций, тултипов и декора,
   которого не будет в платформе.

## Чек-лист приёмки макета (пройти перед этапом 3)

- [ ] Поля доски равны со всех четырёх сторон; зазоры внутри ряда и между рядами одинаковые.
- [ ] Ни один блок не выходит за доску и не пересекается с соседом.
- [ ] Одна метрика не дублируется без объяснения (KPI-тренд и большой график по одной метрике —
  это два раза один смысл).
- [ ] Единица измерения у каждой метрики одна и та же везде, где метрика встречается.
- [ ] Подписи разрезов/категорий не обрезаны и не налезают друг на друга.
- [ ] Период сравнения назван прямо в подписи (например «янв–авг к янв–авг»), а не «+12 %».
- [ ] Заглушки помечены; там, где числа взяты из данных, указан источник и период.
- [ ] Содержимое блоков влезает в габариты — проверено **замером в браузере**, а не только
  координатами из разметки (`scrollHeight` против `clientHeight` по каждому блоку).
- [ ] Ряд фильтров: количество фильтров, их значения, поведение (выпадающий/раскрытый) —
  совпадают с ответами брифа.
- [ ] Заказчик сказал «ок» именно про этот файл (версия макета названа), а не про идею.

## Частые ошибки предпросмотра

- Заглушки «январь…декабрь» и «Группа 1…10» — перенос унылых значений донора. В макете должны
  быть правдоподобные человеческие значения реальных разрезов.
- **Проверка предпросмотра по файлу не видит переполнения блоков.** Координаты, поля и зазоры
  в разметке сходятся, а содержимое блока выше габарита — на экране обрезаны подписи осей и
  хвост таблицы. После сборки открывать страницу в браузере и мерить живую раскладку по каждому
  блоку (`scrollHeight > clientHeight + 1`); инлайн-`<svg>` добавляет лишние ~2 px — лечится
  `svg{display:block}`; высота таблицы считается формулой (шапка + строки × (кегль × 1,45 +
  паддинги)) и сверяется с доступной высотой блока.
- Числа без указания периода: сравнение год-к-году при обрезанном хвосте данных раздувает
  прирост; в подписи должно стоять сопоставимое окно.
- Несоответствие с уже посчитанными числами брифа без объяснения. Если разошлось (13,54 против
  13,59 млн) — причина называется рядом с цифрами: обычно разный набор строк или период.
- Единицы врозь: «млн ₽» невозможно потом подменить на поле модели, если единица склеена
  с числом в один текст. Держать число, единицу и подпись периода разными элементами.
