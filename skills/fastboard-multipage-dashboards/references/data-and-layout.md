# Данные И Композиция

## Зафиксируй Семантику

Пример задачно-ориентированной витрины:

```text
initiative_id, initiative, department, owner,
stage, stage_order, portfolio_group, status,
next_date, reason, deviation_days, success_criteria,
task_id, task, task_status, task_progress,
task_start, task_end, task_owner, snapshot_date
```

Это пример, не обязательные названия полей. Сопоставь с реальной моделью пользователя.

| Вопрос | Корректная мера на зерне задачи |
|---|---|
| Сколько инициатив? | uniqExact(initiative_id) |
| Сколько задач? | uniqExact(task_id) |
| Прогресс инициативы? | согласованная агрегированная мера, например avg(task_progress) |
| Доля завершённых задач? | countIf(task_status = 'Завершена') / count() при уникальной строке task_id |
| Сколько инициатив выполнили критерий? | uniqExactIf(initiative_id, criterion_flag = 1) |

Среднее task_progress не равно готовности стадии. Подпиши методику и при необходимости используй веса.
Если история размножает задачи, count()/avg() без дедупликации неверны: сначала определи актуальную запись.
`any(owner)` допустим только при инварианте одного владельца у инициативы; не маскируй им противоречия источника.

Для взаимоисключающих групп сумма = общий портфель. Для пересекающихся карточек объясни пересечение.
Статус «отменена» не должен раствориться в активном портфеле без явной методики.
Нулевая стадия/статус может отсутствовать в GROUP BY: если пользователь хочет фиксированный полный маршрут, добавь календарь/справочник стадий или иной подтверждённый способ показать нули.

## Макет Как Контракт

Перед сборкой выпиши утверждённое:

- Число уровней и маршруты кликов, включая возврат и закрытие.
- Какие карточки переставлены, какие кнопки исключены.
- Фильтры, множественный выбор, конкретная дата и local/global scope.
- Какие info strips полезны, какие удалены как бессмысленные.
- Какие native-графики сохраняются при рестайле.
- Допустимы ли новые страницы; сохранять ли исходную страницу.

Не называй замену полезной аналитической детализации общими тезисами «доработкой».
Не добавляй промежуточный экран только потому, что так проще реализовать код.

## Главная

Фильтры выше всех контентных блоков. Общий KPI компактный, основная площадь — состоянию портфеля и переходам.
Стадии показываются в логическом порядке, не по размеру столбца. Паспорт/план пилота обычно предшествует пилотированию, но порядок должен подтвердить предметный процесс.
Ближайшие события занимают освободившуюся ширину, а не остаются узкой колонкой с пустотой рядом.
Если блок назван «На контроле», явно определи охват: проблемы, ближайшие даты, готовность к внедрению. Не сужай его молча до одного статуса.

## Групповые Детализации

Полезный базовый ритм: **ряд диаграмм → короткая справка при необходимости → реестр**.

- Внедрение: donut стадий, готовность инициатив, подтверждение критериев. В реестре критерии **конкретной инициативы**, не только общая методичка.
- Эксплуатация: статусы задач, задачи по инициативам, завершение по ведомствам или другой согласованный разрез. Справка — условия стабильной работы, не повтор списка ближайших задач.
- Проблемы: статусы, причины, длительность отклонения. Реестр раскрывает полную причину, владельца, сроки, количество задач. Не нужен декоративный «Фокус решения», если он не добавляет информации.

Данные конкретной задачи важнее этих названий: для продаж, строительства и сервиса формулировки меняются.

## Типографика И Цвет

Бери конкретные токены из согласованного HTML, не навязывай стандартный Soft SaaS при другом дизайне.
Для светлого управленческого контура обычно достаточно 4–6 ролей: cool canvas, белый, tint, ink, muted, accent; дополнительные цвета серий не заменяют роли.
Заголовки диаграмм одного уровня должны иметь одинаковые кегль/жирность. KPI — заметно крупнее подписи.
Отдельные цвета для фонов, подложек и чисел создают иерархию; не делай весь текст акцентным.
Не полагайся только на цвет: статусы, числа, легенды и единицы должны быть читаемы текстом.

## Что Считать Дефектом

- У диаграммы видны столбцы, но скрыта половина названий.
- Название обрезано слева, и потеряна идентичность инициативы.
- Круговая подписана 27/45/27, но пользователь считает, что это количества 3/5/3.
- В карточке высотой с экран только три строки, а полезный реестр ушёл далеко вниз.
- Попап открылся, но его заголовок/крестик выше viewport после клика в нижней таблице.
- Одинаковые задачи двух инициатив слились в одну из-за группировки по названию.
- Фильтр показывает выбор, но KPI и таблицы имеют разные контексты.

Пустота сама по себе не ошибка: оценивай соотношение плотности, задач пользователя и читаемости.
