# Проверка Применимости

## Должен Применяться

1. «Уже согласовали portfolio.html. Собери теперь в FB главную, три детализации и попап задач. Навигацию не меняй». Прочитать HTML, зафиксировать маршруты, проверить модель, собрать native, проверить все уровни.
2. «В детализациях слишком много пустоты. Добавь круговые и столбчатые, UX уже хороший». Менять только композицию нужных экранов, не удалять реестры/критерии и не добавлять новый уровень.
3. «Пишет Ok после сохранения, но карточки не переходят и KPI пустые». Проверить template value и конфликт transitionSettings/goTo, затем native-клики и readback.
4. "Turn the approved prototype into a multipage Fastboard dashboard, with group pages and a task modal." Native widgets, context isolation, id/layers integrity, source-backed acceptance.

## Не Основной Навык

1. «Сделай только HTML, FB пока не трогай». Отдать HTML и не записывать в FB; если скилл уже загружен как контекст проекта, остановиться на HTML.
2. «Поменяй только палитру этой круговой». Использовать fastboard-palettes; не перестраивать страницы и навигацию.
3. «Почему мой SELECT даёт ошибку GROUP BY?» Использовать `dashboard-build` (SQL в форме виджета — в его references), если нет задачи межстраничной сборки.
4. «Сделай дашборд в Excel». Использовать xlsx, не Fastboard.

## Честность Теста

В том же чате можно проверить инструкции и `scripts/`, но нельзя доказать автоматическое срабатывание по description:
оно зависит от того, когда агент перечитает список навыков.
В новом чате проверить один русский и один английский положительный запрос, затем пограничный запрос без упоминания названия навыка. Не обещать, что discovery уже обновился посреди сессии.
